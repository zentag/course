# developing activities

every folder under `activities/by-session/<session>/` and `activities/misc/` is an activity. each one is published to its own repo so students can clone it, fork it, and open PRs:

| folder | repo |
|---|---|
| `activities/by-session/1-exploration/1-git-workflow` | `zentag/course-1-exploration-1-git-workflow` |
| `activities/by-session/2-cad-to-code/1-enums` | `zentag/course-2-cad-to-code-1-enums` |
| `activities/misc/interfaces` | `zentag/course-misc-interfaces` |

each activity repo has two branches:

- `main`: starter code, split from `course:main`
- `solutions`: answer, split from `course:solutions`

**only edit this repo.** the `course-*` repos are generated by `scripts/publish-activities.sh`. anything committed there directly will block the next publish (or get wiped by `--force`).

## the solutions branch

`solutions` = `main` + answers.

- only ever merge `main` → `solutions`, never the other way, or answers leak into the starters
- merge `main` into `solutions` before publishing so READMEs and build files match
- see one activity's answer: `git diff main solutions -- activities/<path>`

## new activity

1. on `main`, add `activities/by-session/<n>-<session>/<k>-<name>/` (or `activities/misc/<name>/`) with the starter code and a `README.md`. commit and push
2. `git checkout solutions && git merge main`, write the answer in the same folder, commit and push
3. `scripts/publish-activities.sh <k>-<name>`: creates the repo and pushes both branches

## change a starter

1. edit on `main`, commit, push
2. `git checkout solutions && git merge main`, fix any conflicts in the answer, commit, push
3. `scripts/publish-activities.sh <name>`

## change only a solution

edit on `solutions`, commit, push, `scripts/publish-activities.sh <name>`

## publishing

```sh
scripts/publish-activities.sh               # every activity
scripts/publish-activities.sh 1-enums misc/  # anything whose path contains a filter
scripts/publish-activities.sh --force ...    # only after rewriting history
```

needs `gh` logged in. `git subtree split` is deterministic, so republishing is a fast-forward that only adds the new commits touching that folder, and students can just `git pull`. activities that only exist on `solutions` (like `misc/9431-intake`) get only a `solutions` branch.

renaming/moving a folder changes its repo name, so a new repo gets made. `gh repo rename` the old one first if you want to keep it.

## if someone committed to a course-* repo

pull it back into the monorepo on the matching branch, then republish:

```sh
git subtree pull --prefix=activities/<path> https://github.com/zentag/course-<name>.git <branch>
```

## students

- clone/fork `zentag/course-<name>`, open a PR to `main`
- answer: `git fetch origin solutions && git diff main origin/solutions`, or switch branches on GitHub
